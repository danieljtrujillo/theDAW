## DJ

A full two-deck DJ console backed by a real, self-contained Web Audio engine (`frontend/src/state/djEngine.ts`). Each deck decodes its track to an `AudioBuffer` and plays through a per-deck chain — trim -> volume -> 3-band EQ -> single-knob filter -> optional FX -> equal-power crossfader — summed at a brickwall-limited DJ master. The entire console runs locally in the browser; only two optional Controller Vision helpers touch the network.

### Decks and mixing
- **Two independent decks** with a jog-wheel platter, pitch fader (drives `playbackRate`), 3-band EQ (lowshelf 120 Hz / peaking 1 kHz / highshelf 3.2 kHz), and a single-knob DJ filter that sweeps low-pass or high-pass from a flat center. (`djEngine.ts:231`, `:697`)
- **Equal-power crossfader** (cos/sin) keeps loudness constant across the blend, into a **brickwall limiter** on the DJ bus for clip safety (`DynamicsCompressorNode`, threshold -1.5 dB, ratio 20). (`djEngine.ts:225`, `:166`)
- **Auto-gain** levels decks toward a -12 dB target from the analyzed RMS, so tracks match without riding the gain. (`DJView.tsx:300`)

### Performance
- **Sample-accurate cue, hotcues (4/deck), beat loops, loop-roll, beat-jump, and slip** using native buffer `loopStart/loopEnd` so wraps are click-free; cue points can quantize to the beat grid. (`djEngine.ts:345`, `:929`)
- **Vinyl scratch** via a dedicated `AudioWorklet` ('vinyl-scratch') with a hand-driven read-head and two voices — `classic` (clean turntable) and `cyber` (sample-hold + ~5-bit crush) — plus motor spin-up/wind-down ramps. (`frontend/public/vinyl-scratch.worklet.js`)
- **Onboard FX rack** per deck: flanger, wah, and a reverb whose impulse response is generated at runtime (no IR file bundled). Built lazily on first knob touch. (`djEngine.ts:735`)
- **10-pad sampler** of one-shots through the DJ master, polyphonic with loop-toggle and choke groups; assignments persist. (`djEngine.ts:857`, `DJView.tsx:1142`)

### Tempo, key, and mixing intelligence
- **Key-lock (master tempo)** holds pitch while tempo moves, using the **`signalsmith-stretch` ^1.3.2** WASM node as a live pitch corrector (`-12*log2(rate)`), lazy-loaded on first enable with cross-deck latency compensation. (`package.json:41`, `djEngine.ts:629`)
- **BPM Sync + Sync-Lock** beatmatch and phase-lock the follower deck; pitch range is +/-10% or +/-15%. (`DJView.tsx:727`, `:773`)
- **Beat grid + BPM/key** come from a local analysis backend at `/api/analysis/{id}` — **aubio** for tempo/beats (librosa beat-tracker fallback), **librosa** for key (`chroma_cqt`), pitch (`librosa.pyin`), bars and RMS. (`backend/modules/analysis/router.py:38`)
- **Camelot harmonic matching** is derived client-side (dependency-free) to flag compatible next keys. (`frontend/src/lib/camelot.ts`)
- **Automix** auto-sequences the active setlist across both decks: beatmatch near the tail (18 s), crossfade (10 s), advance. (`DJView.tsx:932`)

### Stems on a deck
- A deck can switch to **live stem mode** — each separated stem plays in lock-step through its own fader/mute pad. Separation runs on a local **Demucs** sidecar (stem counts 2/4/6/12), re-encoded to PCM_16; DB records model `demucs`. (`djEngine.ts:1008`, `backend/modules/stems/engine.py:239`)

### Controllers
- **MIDI-learn**: bind any CC/note to DJ actions (crossfader, transport, EQ, filter, volume, pitch, hotcues, stem toggles); ships a **Novation Launch Control XL** preset. (`DJView.tsx:129`, `djControlMap.ts`)
- **Headphone cue** pre-listens a deck on a second output device via `MediaStreamAudioDestinationNode` + `setSinkId`. (`djEngine.ts:180`)
- **Controller Vision** recognizes a controller's layout from a photo — classical **OpenCV** (Hough circles + contour shapes, CPU, no model), an optional vision-LLM identify path (models used verbatim: `gemini-flash-latest`, `claude-sonnet-4-6`, `gpt-4.1-mini`, `grok-3`, `google/gemini-flash-1.5`), Wikimedia image lookup, and phone-over-LAN QR capture. Mapping still comes from MIDI-learn. (`backend/modules/controllervision/engine.py`)

### Runs offline
Every core DJ function is local Web Audio. Analysis and stem separation run on the local backend (Demucs downloads weights once, then works offline). The only network-dependent features are optional and confined to Controller Vision: the AI vision-LLM identify path (needs a configured API key) and the Wikimedia image fetch; the OpenCV path and phone LAN capture need no cloud.
